Cryptographic Hash Functions

Study and implement a cryptographic hash function to generate a fixed-length hash value for a given input message.

Aim & Objectives

Aim: To study, implement, and analyze the fundamental principles of Cryptographic Hash Functions, focusing on the legacy standards MD5 (128-bit) and SHA-1 (160-bit), to understand message padding, deterministic digest generation, and the avalanche effect.

Objectives:

  • Understand the One-Way Primitive: Grasp the mathematical concept of fixed-length digest generation and the three security pillars: Pre-image resistance, Second pre-image resistance, and Collision resistance.
  • Analyze Digest Mechanics (MD5 vs SHA-1): Observe how variable-length input strings are processed into uniform 512-bit message blocks to yield 128-bit (MD5) and 160-bit (SHA-1) hexadecimal outputs.
  • Observe Deterministic Behavior: Confirm that identical inputs consistently produce identical digests across runs, regardless of string length.
  • Demonstrate the Avalanche Effect: Examine how flipping a single character or bit in the plaintext cascades into a complete, unpredictable transformation of the output digest.
  • Examine Cryptanalytic Security: Understand why collision vulnerabilities led to the deprecation of MD5 and SHA-1 in modern security standards.

Theory

Part 1: The Prologue: The Digital DNA and The One-Way Black Hole

Imagine taking the entire text of the Encyclopaedia Britannica (millions of words, historical accounts, and images) and feeding it into a mathematical algorithm. In less than a millisecond, it outputs a tiny, fixed string of 32 characters: 

7d793037a0760186574b0282f2f435e7

Now imagine you open that massive encyclopedia, change just one single comma into a period, and run it again. The new output does not change by 1%. It completely scrambles into something unrecognizable: 

4a9f3b1e88c023d517e411b98a12dc08

Even more baffling: you can never turn that 32-character string back into the original book. It is a mathematical black hole. Information can fall in, but it cannot crawl back out.

Why Cryptographic Hash Functions are the Backbone of the Digital World:

  • Git Version Control: Detects if even one byte of source code has changed across commits.
  • Authentication and Passwords: Allows servers to verify passwords without ever storing plaintext passwords in a database.
  • Blockchain Networks: Links immutable blocks and protects decentralized consensus mechanisms.
  • Software Integrity: Confirms that downloaded operating system updates have not been intercepted or altered by an attacker.

Part 2: Cryptographic Riddles: Everyday Intuition

Riddle 1: The Blender Analogy (Can You Un-blend a Smoothie?)

If you put an apple, a banana, and strawberries into a blender, you get a fruit smoothie in seconds. But if someone hands you a glass of that smoothie, can you turn it back into the original whole apple?

The Takeaway: That is the one-way property. Creating a hash from your text takes less than a millisecond, but turning that hash back into your original text is mathematically impossible.

Riddle 2: The Domino Flip (The One-Letter Mystery)

Suppose you generate an MD5 hash of the word "password". Now you change just the first letter to capital "Password". Does only the first character of the hash change?

The Takeaway: No! The entire 32-character string completely scrambles into something unrecognizable. Like knocking down a single domino that flips every switch in a building, changing even one tiny letter changes the entire output. This is called the Avalanche Effect.

Riddle 3: The Universal Suitcase (One Size Fits All)

If you hash a tiny message with just one letter "A", and then hash a gigantic file like a 2-hour movie, which one produces a longer hash?

The Takeaway: Neither! Both outputs have the exact same length (32 characters for MD5, 40 characters for SHA-1). No matter how small or large the input is, a cryptographic hash always packs it into a strictly fixed-size digital fingerprint.

Part 3: Fundamentals of Cryptographic Hash Functions

Definition: A cryptographic hash function is a deterministic mathematical algorithm that compresses an arbitrary, variable-length block of binary data into a strictly fixed-size bit string (termed the message digest or hash value). It operates strictly as a one-way function, meaning that while computing the digest from any message is computationally instantaneous, computing the original message from the digest is computationally infeasible.

Why Necessary and Crucial in Modern Security:

  • The Digital Signature Bottleneck: Asymmetric cryptography algorithms like RSA or ECC are mathematically heavy and computationally slow. Signing a 500 MB file directly with an RSA private key would require unacceptable processing time. Instead, the sender hashes the 500 MB file into a tiny 128-bit or 160-bit digest and signs only that fixed digest, achieving instant signature generation with zero loss of cryptographic proof.
  • Integrity Protection Against Active Adversaries: Simple checksums like CRC-32 only guard against random hardware noise (such as an electrical spike flipping a bit on an Ethernet cable). A malicious hacker can easily manipulate bits in a file so that the resulting CRC-32 checksum remains unchanged. Cryptographic hash functions provide tamper-evident security that prevents active attackers from modifying data undetected.
  • Secure Credential Authentication: When a user registers a password, a secure server does not store the plaintext password. Instead, it salts and hashes the password and stores only the digest. When the user logs in, the server re-hashes the input password and checks for a match, protecting user credentials even if the backend database is leaked.
  • Message Authentication Codes (HMAC): Combining cryptographic hash functions with secret keys allows systems to verify both data integrity and message authenticity simultaneously.

Where Used Across Digital Systems:

  • TLS and SSL Certificate Chains: Validates web server identity and ensures certificate authenticity.
  • Operating System Package Repositories: Package managers (like Debian APT, Red Hat RPM, and Homebrew) verify cryptographic hashes before installing software packages to prevent malicious mirror tampering.
  • Version Control Infrastructure: Systems like Git track directory snapshots, commits, trees, and file blobs using their cryptographic hash identifiers.
  • Cloud Storage Deduplication: Cloud providers (like Dropbox or Google Drive) compute file hashes to identify duplicate uploads across millions of users, saving petabytes of storage.

The Three Security Pillars (Mathematical Criteria):

  • Pre-image Resistance (One-Way Property): Given an output digest y = H(x), it must be computationally infeasible to discover any valid input message x. For an n-bit hash function, finding a pre-image requires brute-force search with an average work factor of 2n evaluations.
  • Second Pre-image Resistance (Weak Collision Resistance): Given a specific input message x1, it must be computationally infeasible to find a distinct message x2 ≠ x1 such that H(x1) = H(x2). This property guarantees that an attacker cannot replace a signed legal contract with a fraudulent contract that produces the same hash. The work factor required is 2n evaluations.
  • Collision Resistance (Strong Collision Resistance): It must be computationally infeasible to find any pair of distinct inputs x1 ≠ x2 such that H(x1) = H(x2). Because of the mathematical Birthday Paradox (the probability of any two items matching in a shared pool), finding an arbitrary collision requires only 2n/2 evaluations. For a 128-bit hash like MD5, collision resistance drops to 264 operations, not 2128.

The Merkle-Damgard Construction Paradigm:

Because mathematical compression functions can only process fixed-size input chunks, both MD5 and SHA-1 use the Merkle-Damgard iterative framework. An arbitrary-length message is first padded and sliced into uniform blocks of 512 bits each (M1, M2, ... Mk). An Initial Vector (IV) represents the starting state. Each 512-bit message block is sequentially fed into a compression function f along with the chaining state from the previous block: 

State_0 = IV
State_1 = f(State_0, M_1)
State_2 = f(State_1, M_2)
...
Final_Digest = f(State_{k-1}, M_k)

Merkle-Damgard Strengthening: Appending the exact 64-bit length of the original message to the final block mathematically proves that if the underlying compression function f is collision resistant, the entire iterated hash function is also collision resistant.

Part 4: Deep Dive into MD5 (Message Digest 5)

Definition: Designed in 1991 by Ronald Rivest (MIT) to replace MD4 (RFC 1321), MD5 processes message streams in uniform 512-bit blocks to produce a 128-bit digest (formatted as 32 hexadecimal characters). It is built specifically for high-speed software execution on 32-bit CPU architectures using little-endian byte ordering.

Why Important in Computing History: MD5 was the dominant global cryptographic hashing standard for nearly two decades. It underpinned early internet security, BSD and Linux password authentication, and software distribution validation (the ubiquitous md5sum utility).

Where Used Today: MD5 is strictly limited to non-cryptographic checksum verification (such as detecting accidental file corruption on local disk drives) and hash table partitioning. It is explicitly prohibited for digital signatures, certificates, and authentication.

Comprehensive 5-Step Internal Working:

  1. Step 1: Bit Padding: The input message is padded so its total length in bits is congruent to 448 modulo 512. Padding always takes place, even if the message already has the desired length. Padding consists of appending a single bit '1' followed by as many '0' bits as required (between 1 and 512 padding bits).
  2. Step 2: Append 64-Bit Length: A 64-bit representation of the original message length (in bits, taken modulo 264) is appended to the message. The length is appended as two 32-bit words in little-endian order (least significant byte first). The message is now an exact multiple of 512 bits (64 bytes).
  3. Step 3: Initialize Four 32-Bit Chaining Registers: A four-word state buffer (A, B, C, D) is initialized using predefined hexadecimal constants in little-endian byte order:
    • Register A: 0x67452301
    • Register B: 0xEFCDAB89
    • Register C: 0x98BADCFE
    • Register D: 0x10325476
  4. Step 4: Execute 4 Processing Rounds (64 Step Operations): Each 512-bit block is parsed into sixteen 32-bit words: M[0] to M[15]. The block is processed through 4 distinct rounds with 16 steps each (64 total steps). Each round employs a unique non-linear logic function:
    • Round 1 (Steps 0 to 15): F(X, Y, Z) = (X ∧ Y) ∨ (¬X ∧ Z) (Conditional: if X then Y else Z)
    • Round 2 (Steps 16 to 31): G(X, Y, Z) = (X ∧ Z) ∨ (Y ∧ ¬Z) (Conditional: if Z then X else Y)
    • Round 3 (Steps 32 to 47): H(X, Y, Z) = X ⊕ Y ⊕ Z (Bitwise XOR parity)
    • Round 4 (Steps 48 to 63): I(X, Y, Z) = Y ⊕ (X ∨ ¬Z) (Inverted non-linear mixing)

    The step transformation formula is:

    A = B + ((A + f(B, C, D) + M[k] + T[i]) &lll; s)

    Where T[i] are 64 constant table words derived from the integer part of 232 × |sin(i+1)|, &lll; s represents circular left bit rotation by s positions, and the registers rotate cyclically: D becomes A, C becomes D, B becomes C, and the computed result becomes B.

  5. Step 5: State Accumulation and Final Digest: After processing all 64 steps, the resulting registers are added modulo 232 to their initial values: A = A + A_init, B = B + B_init, C = C + C_init, D = D + D_init. When all 512-bit blocks are exhausted, the four registers are serialized in low-order byte first order to yield the final 128-bit digest.

Vulnerabilities, Cryptanalysis, and Historical Demise:

  • Xiaoyun Wang Collision Discovery (2004): Chinese cryptanalyst Professor Xiaoyun Wang and her research team announced practical collision attacks against MD5, finding collisions in just a few hours on an IBM computer.
  • Rogue Certificate Authority Forgery (2008): Security researchers generated a valid, rogue SSL Certificate Authority certificate using chosen-prefix MD5 collisions, proving that attackers could intercept HTTPS encrypted traffic.
  • The Flame Cyberweapon (2012): The sophisticated Flame malware exploited MD5 collisions to forge code-signing certificates from Microsoft Terminal Server licensing, enabling it to masquerade as an official Windows Update.

Part 5: Deep Dive into SHA-1 (Secure Hash Algorithm 1)

Definition: Published by NIST and the NSA in 1995 (FIPS PUB 180-1), SHA-1 produces a 160-bit digest (40 hexadecimal characters) from 512-bit message blocks using five 32-bit registers. It was developed to fix an undisclosed mathematical vulnerability in the original 1993 SHA-0 standard by introducing a single circular shift in its message expansion schedule.

Why Important in Computing History: SHA-1 was the mandatory federal standard designed to replace MD5. It served as the security backbone of TLS 1.0, SSH, IPSec, PGP, and S/MIME. It was also chosen by Linus Torvalds as the content-addressable identifier for all Git commits and file trees.

Where Used Today: SHA-1 is now deprecated across all major security protocols. It remains in legacy Git installations (with modern Git transitioning to SHA-256) and historical audit databases. Major web browsers have completely rejected SHA-1 SSL certificates since 2017.

Comprehensive 5-Step Internal Working:

  1. Step 1: Big-Endian Padding and Length Appending: The padding rules match MD5 (append '1', pad zeros to 448 bits modulo 512, append 64-bit length), but all 32-bit words and the 64-bit message length are interpreted and stored in big-endian byte order (most significant byte first).
  2. Step 2: Initialize Five 32-Bit Chaining Registers: A five-word state buffer (A, B, C, D, E) is initialized with the standard Secure Hash initial constants:
    • Register A: 0x67452301
    • Register B: 0xEFCDAB89
    • Register C: 0x98BADCFE
    • Register D: 0x10325476
    • Register E: 0xC3D2E1F0
  3. Step 3: Message Schedule Expansion (Wt): The critical innovation in SHA-1. Each 512-bit block provides sixteen 32-bit words (M0 to M15). SHA-1 expands these 16 words into 80 distinct 32-bit words (W0 to W79):
    • For t = 0 to 15: Wt = Mt
    • For t = 16 to 79: Wt = (Wt-3 ⊕ Wt-8 ⊕ Wt-14 ⊕ Wt-16) &lll; 1

    The circular 1-bit rotation in the expansion formula ensures that any single-bit input difference rapidly disperses across all 80 computation steps.

  4. Step 4: Execute 4 Processing Rounds (80 Step Operations): SHA-1 executes 4 rounds with 20 steps each (80 total steps). Each round utilizes a non-linear logic function ft and a fixed hexadecimal additive constant Kt:
    • Round 1 (Steps 0 to 19): ft = (B ∧ C) ∨ (¬B ∧ D), Constant K1 = 0x5A827999
    • Round 2 (Steps 20 to 39): ft = B ⊕ C ⊕ D (Parity), Constant K2 = 0x6ED9EBA1
    • Round 3 (Steps 40 to 59): ft = (B ∧ C) ∨ (B ∧ D) ∨ (C ∧ D) (Majority), Constant K3 = 0x8F1BBCDC
    • Round 4 (Steps 60 to 79): ft = B ⊕ C ⊕ D (Parity), Constant K4 = 0xCA62C1D6

    The step transformation formula is:

    TEMP = (A &lll; 5) + f_t(B, C, D) + E + W_t + K_t E = D D = C C = (B &lll; 30) B = A A = TEMP
  5. Step 5: Final Output Assembly: After completing step 79, each register is added modulo 232 to its pre-block value: A = A + A_init, B = B + B_init, C = C + C_init, D = D + D_init, E = E + E_init. The five registers are concatenated in big-endian order to yield the final 160-bit digest (40 hexadecimal characters).

Cryptanalysis and The SHAttered Attack:

  • Theoretical Weakness (2005): Xiaoyun Wang, Yiqun Lisa Yin, and Hongbo Yu proved that SHA-1 collisions could be found in 269 operations, breaking the theoretical 280 security bound.
  • The Google / CWI SHAttered Milestone (2017): Researchers at CWI Amsterdam and Google produced the world's first practical SHA-1 collision. They created two distinct PDF documents with different visual content (one with blue background, one with red) that generated the identical SHA-1 hash. The attack required 9 quintillion SHA-1 calculations (equivalent to 6,500 CPU years).
  • Final NIST Deprecation (2022 to 2030): NIST officially transitioned away from SHA-1 for digital signatures in 2011, and in December 2022 issued a formal directive to retire SHA-1 in all federal applications by December 31, 2030 in favor of SHA-2 and SHA-3.
