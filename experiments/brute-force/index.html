Brute Force Attack

Learn how password guessing works and why longer passwords are harder to guess.

Theory: Brute-Force Attack

Aim

To understand the basic working of a brute-force password attack through a safe, local demonstration and learn why password length matters.

Objectives

  • Understand what a brute-force attack is.
  • Learn about character sets and password length.
  • Calculate the number of possible combinations.
  • Observe candidate guesses, attempts and progress.
  • Identify practical ways to improve password security.

1. What is a brute-force attack?

A brute-force attack tries possible password combinations in a systematic order until a match is found. The larger the set of possible passwords, the more guesses may be needed.

2. How does it work?

For example, if the target password is "aba", the simulator changes one letter at a time, like a counter rolling over. The underlined letter in each guess is the one that just changed from the previous guess: 

Guess 1:  aaa
Guess 2:  aab
Guess 3:  aac
Guess 4:  aad
Guess 5:  aae
Guess 6:  aaf
Guess 7:  aag
Guess 8:  aah
Guess 9:  aai
Guess 10: aaj
...
Guess 23: aaw
Guess 24: aax
Guess 25: aay
Guess 26: aaz   (last letter has cycled through a–z)
Guess 27: aba   match found! (middle letter moved from a → b, last letter reset to a)

It took 27 attempts to reach "aba". A password like "zzz" would be the very last of the 17,576 possible combinations.

  1. Choose the characters that may be used.
  2. Generate a candidate password.
  3. Check whether the candidate matches the target in the demonstration.
  4. If it does not match, try the next candidate.
  5. Stop when a match is found or the experiment ends.

Real websites should not reveal passwords for direct comparison. They use secure password verification and security controls.

3. What is a character set?

A character set is the group of characters allowed in a password. For example, lowercase English letters have 26 characters: a through z. A set can also include uppercase letters, digits or symbols.

4. What is the search space?

The search space is the total number of possible combinations for the chosen character set and password length. 

Search space = C^L

C is the number of available characters.

L is the password length.

For 26 lowercase letters and a 3-character password: 26³ = 17,576 combinations.

The simulator does not always need to test every combination. It stops if it finds the target earlier.

5. Brute force vs. dictionary attack

A brute-force method systematically tries combinations from a defined set. A dictionary attack tries candidates from a list of common words or likely passwords. Both are password-guessing approaches, but they choose candidates differently.

6. Why does password length matter?

Each extra character creates more possible combinations. With 26 lowercase letters, a one-character password has 26 combinations, while a two-character password has 676. Longer, unpredictable passwords are generally harder to guess.

7. Why can the time vary?

Time depends on how quickly guesses are tested, the size of the search space, the order of guesses and security controls. This browser demo is for learning and does not represent real-world cracking speeds.

8. How can brute-force attacks be prevented?

  • Use long, unique passwords or passphrases.
  • Use a password manager.
  • Enable multi-factor authentication (MFA).
  • Apply rate limits and monitor suspicious sign-ins.
  • Store passwords using secure salted password-hashing methods.

Learning outcome

By the end, you should be able to explain brute-force guessing, calculate a simple search space, interpret simulation results and suggest basic password protections.

For education only. The simulation runs locally and does not connect to real accounts or systems.

Procedure

Follow these steps to see how the simulator guesses a short sample password. You do not need any prior knowledge to try it.

Before you start

Target password: the sample value the simulator is trying to find. Use a made-up example, not a real password.

Character set: the characters the simulator is allowed to use. For example, lowercase letters means a, b, c … z.

How to perform the experiment

  1. Open the Simulation tab.
  2. Enter a short sample target such as ab.
  3. Select a character set that contains every character in your target.
  4. Review the total number of possible combinations.
  5. Press Start. The simulator generates guesses in a defined order.
  6. Watch the current guess, attempt count, progress and elapsed time.
  7. If a guess is wrong, the simulator tries another. When it finds the target, it stops and shows a success message.
  8. Use Pause to pause and Resume to continue. Use Reset to start a fresh experiment.

Understand the formula

Search space = C^L

C = number of available characters at each position.

L = number of characters in the password.

C^L = total possible combinations.

Example: 3 lowercase letters

There are 26 lowercase letters, so C = 26. If the password has 3 characters, L = 3. 

26^3 = 26 × 26 × 26 = 17,576 combinations

Why multiply 26 three times? Each of the three positions can contain any of the 26 letters.

Two smaller examples

  • Length 1: 26¹ = 26 combinations.
  • Length 2: 26² = 26 × 26 = 676 combinations.

Notice how the total grows quickly as the password gets longer.

Does it always try every combination?

No. The search space is the total number of possible candidates, but the simulator stops as soon as it finds the target. The number of actual attempts depends on where the target appears in the guessing order.

What do the results mean?

  • Current guess: the candidate being checked most recently.
  • Attempts: how many candidates have been checked so far.
  • Total combinations: the size of the complete search space.
  • Progress: the fraction of that search space already checked.
  • Elapsed time: time spent in this browser demonstration, not a real-world cracking estimate.
  • Attempts per update: how many guesses are processed before the display refreshes. A larger batch may run faster but makes individual guesses less visible; it does not change the search space.

Conclusion

The experiment shows that the number of possible passwords depends on character-set size and length. Using long, unique passwords and enabling multi-factor authentication makes accounts more resistant to password guessing.

Quick interpretation

A larger character set or a longer target means more possible candidates. The simulator stops when it finds a match, so attempts may be fewer than the total combinations. This demo's elapsed time reflects browser performance, not the speed of a real attack.
