RSA Digital Signature with Hash

To generate the SHA-256 hash of a message, create an RSA digital signature using the hash and private key, verify the signature using the corresponding public key, and demonstrate message integrity through tamper detection.

Aim & Objectives

Aim: To generate the SHA-256 hash of a message, create an RSA digital signature using the hash and private key, verify the signature using the corresponding public key, and demonstrate message integrity through tamper detection.

Objectives:

  • Understand the "hash-then-sign" paradigm in digital signature algorithms.
  • Observe why hashing is necessary to prevent existential forgery and manage arbitrarily large messages.
  • Perform RSA signature generation using private key d and signature verification using public key e.

Theory

1. Introduction to Digital Signatures

A digital signature is a cryptographic mechanism for verifying the authenticity and integrity of digital messages or documents. Analogous to a traditional handwritten signature or stamped seal, a valid digital signature provides the recipient with strong cryptographic proof that the message was created by a known sender (authentication), that the sender cannot deny having sent the message (non-repudiation), and that the message was not altered in transit (integrity).

2. The RSA Key Pair

The RSA cryptosystem, developed by Ron Rivest, Adi Shamir, and Leonard Adleman in 1977, is an asymmetric algorithm based on the computational difficulty of factoring the product of two large prime numbers.

  • Modulus n: Computed as n = p × q.
  • Euler's Totient φ(n): Calculated as φ(n) = (p - 1)(q - 1).
  • Public Exponent e: Typically 65537.
  • Private Exponent d: Computed as the modular multiplicative inverse of e modulo φ(n).

3. The "Hash-Then-Sign" Paradigm & SHA-256

The signer first applies SHA-256 to the message to produce a fixed-length 256-bit message digest.

h = H(M) = SHA-256(M)

SHA-256 provides preimage resistance, second-preimage resistance, and collision resistance.

4. RSA Digital Signature Equations

  • Signature Generation:
    s = (h)d mod n
  • Transmission: The message and digital signature are transmitted to the verifier.
  • Signature Verification:
    h' = (s)e mod n
    The verifier independently calculates:
    hcomputed = SHA-256(M')
  • Decision Rule: If both hashes match, the signature is VALID.

5. Why Message Tampering Causes Verification Failure

Cryptographic hash functions demonstrate the avalanche effect. A small modification to the original message produces a completely different hash value. Therefore, when a modified message is verified against the original signature, the newly calculated SHA-256 hash will not match the digest contained within the signature.

Procedure

  1. Select or generate the RSA key pair parameters (modulus n, public exponent e, and private exponent d).
  2. Enter the plaintext message and generate its cryptographic hash using SHA-256.
  3. Use the resulting SHA-256 hash as the input for RSA signing using the private key.
  4. View the generated digital signature in hexadecimal and Base64 representations.
  5. Verify the signature using the RSA public key and compare the recovered digest with the SHA-256 hash of the verification message.
