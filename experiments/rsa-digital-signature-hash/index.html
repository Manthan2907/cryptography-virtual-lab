Theory

1. Introduction to Digital Signatures

A digital signature is a cryptographic mechanism for verifying the authenticity and integrity of digital messages or documents. Analogous to a traditional handwritten signature or stamped seal, a valid digital signature provides the recipient with strong cryptographic proof that the message was created by a known sender (authentication), that the sender cannot deny having sent the message (non-repudiation), and that the message was not altered in transit (integrity).

2. The RSA Key Pair

The RSA cryptosystem, developed by Ron Rivest, Adi Shamir, and Leonard Adleman in 1977, is an asymmetric algorithm based on the computational difficulty of factoring the product of two large prime numbers.

  • Modulus n: Computed as n = p × q.
  • Euler's Totient φ(n): Calculated as φ(n) = (p - 1)(q - 1).
  • Public Exponent e: Typically 65537.
  • Private Exponent d: Computed as the modular multiplicative inverse of e modulo φ(n).

3. The "Hash-Then-Sign" Paradigm & SHA-256

The signer first applies SHA-256 to the message to produce a fixed-length 256-bit message digest.

h = H(M) = SHA-256(M)

SHA-256 provides preimage resistance, second-preimage resistance, and collision resistance.

4. RSA Digital Signature Equations

  • Signature Generation:
    s = (h)d mod n
  • Transmission: The message and digital signature are transmitted to the verifier.
  • Signature Verification:
    h' = (s)e mod n
    The verifier independently calculates:
    hcomputed = SHA-256(M')
  • Decision Rule: If both hashes match, the signature is VALID.

5. Why Message Tampering Causes Verification Failure

Cryptographic hash functions demonstrate the avalanche effect. A small modification to the original message produces a completely different hash value. Therefore, when a modified message is verified against the original signature, the newly calculated SHA-256 hash will not match the digest contained within the signature.

Step-by-step practical

Procedure

Follow these steps in order to generate a signature, verify the original message, and test whether a change to the message is detected. Use the Simulation tab for the interactive controls and outputs.

1

Prepare the RSA key pair

In the Simulation tab, click Generate Random Key to populate the RSA key fields, then click Use This Key. The public key contains the modulus n and exponent e; the private exponent d must be kept secret.

2

Enter the original message

Enter a message in the signing section, for example, “Transfer 1000 INR to Alice.” Use the same message for the first verification test.

3

Generate the SHA-256 digest

Click the relevant Generate SHA-256 control. Observe the digest and note that SHA-256 produces a fixed 256-bit output, commonly displayed as 64 hexadecimal characters.

4

Create the digital signature

Click Create RSA Digital Signature in the signing section. The application hashes the message and signs the digest using the RSA private key. Observe the signature in hexadecimal and Base64 formats.

5

Verify the original message

Use the same message and the generated signature in the verification section, then click Verify Signature. A valid result indicates that the signature matches the message and corresponding public key.

6

Modify the message

Change one character, word, or number in the message while keeping the original signature unchanged. Generate or inspect the new SHA-256 digest and compare it with the original digest.

7

Verify the modified message

Verify the modified message against the original signature. The verification should fail because the digest of the modified message does not match the digest associated with the original signature.

Observations to record

  • The SHA-256 digest is 256 bits long regardless of the message length.
  • The original message and its signature should pass verification when the correct key pair is used.
  • A small change in the message normally produces a substantially different SHA-256 digest.
  • The original signature should not validate the modified message.
  • Hexadecimal and Base64 are encodings for displaying signature bytes; neither is the signature algorithm itself.

2. Use the Hash for RSA Signing

Now that you have seen how SHA-256 creates the message digest, the digest can be used in the RSA digital signature process.

Sender's RSA Keys

Enter the sender's public key (n, e) and private key d (decimal, or hexadecimal starting with 0x). New to RSA? Just click Generate Random Key and the boxes fill themselves.

An RSA key pair has two parts:
• Public key (n, e) — shared with everyone. It is used to verify signatures.
• Private key d — known only to the sender. It is used to create signatures.

The two keys are mathematically linked, so a random d will not work with a given (n, e) — the simulation checks this for you. Because the SHA-256 digest is padded (PKCS#1 v1.5) before signing, n must be at least 512 bits.
