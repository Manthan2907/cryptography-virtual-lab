Generation & verification of MAC tags using shared secret keys — CBC-MAC, CMAC (NIST SP 800-38B), and Keyed-MAC.

Aim & Objectives

The primary objective of this experiment is to implement, analyze, and verify a Message Authentication Code (MAC) for arbitrary messages using a shared secret key K. Students will explore block-cipher based MAC constructions (CBC-MAC and CMAC — NIST SP 800-38B) alongside a general keyed MAC function C(K, M) → T to evaluate data integrity and data origin authentication.

What is a Message Authentication Code (MAC)?

A Message Authentication Code (MAC), also known as a cryptographic tag or checksum, is a symmetric key cryptographic algorithm that takes an arbitrary-length message payload M and a shared secret key K, and produces a fixed-size authentication tag T:

Tag T = MAC(K, M) ≡ C(K, M)

Only parties who possess the secret key K can compute or verify the tag T. If an adversary modifies even 1 bit of M or T, the receiver’s verification algorithm returns INVALID.

Block-Cipher Based MAC Constructions

1. CBC-MAC (Cipher Block Chaining MAC)

CBC-MAC uses a block cipher (AES-128) in Cipher Block Chaining mode. The message M is divided into 128-bit blocks P1, P2, …, Pn. Each block is XORed with the previous cipher block before encryption:

T₀ = 0¹²⁸ (Initialization Vector) T₁ = E_K( P₁ ⊕ T₀ ) T₂ = E_K( P₂ ⊕ T₁ ) ⋮ Final Tag T = T_n

2. CMAC (NIST SP 800-38B Standard)

CMAC fixes the security limitations of raw CBC-MAC for variable-length messages by generating two 128-bit subkeys (K1 and K2) from the primary key K using Galois field finite-field multiplication:

L = E_K(0¹²⁸) K₁ = L << 1 (XOR 0x87 if MSB=1) K₂ = K₁ << 1 (XOR 0x87 if MSB=1) Last Block = P_n ⊕ K₁ (or K₂ if padded)

3. General Keyed-MAC

A general keyed MAC uses a cryptographic hash function parameterized by a secret key. Unlike a plain hash, the key is required to reproduce the tag, providing authenticity. In this simulation, we use the secret-prefix construction:

MAC(K, M) = SHA-256(K ∥ M) (Key prepended to message before hashing)

Security Properties: MAC vs. Hash vs. Digital Signature

Security Mechanism Key Used Data Integrity Authentication Non-Repudiation
Cryptographic Hash (SHA-256) None Yes (accidental noise) No No
MAC (CBC-MAC / CMAC / Keyed-MAC) Shared Secret K Yes (active tampering) Yes (key holder) No (both hold K)
Digital Signature (RSA / ECDSA) Asymmetric (Private/Public) Yes Yes Yes (only sender holds Private Key)

Length-Extension Vulnerability & Real-World Use

The simple secret-prefix Keyed-MAC is vulnerable to length-extension attacks on Merkle-Damgård hash functions: an attacker who knows MAC(K, M) and the length of K ∥ M can forge a MAC for M ∥ padding ∥ M' without knowing K. CMAC was specifically designed to be immune to this class of attacks.

  • Verifying API payloads (e.g., Stripe webhooks, AWS Signature V4).
  • Message authentication in network protocols (SSL/TLS record layer).
  • Verifying software update packages and firmware images.
  • Authentication in banking and financial messaging (SWIFT, ISO 8583).

Expected Observations

  • The same key + message always produces the same MAC tag (deterministic).
  • Even a single character change in the message produces a completely different tag (avalanche effect).
  • An incorrect key produces a different tag — MAC verification fails.
  • CBC-MAC and CMAC tags are always 32 hex characters (128 bits); Keyed-MAC tags are 64 hex characters (256 bits).

Self-Assessment Quiz

Test your understanding of Message Authentication Codes (MAC). Select an answer for each question and click Submit for instant explanations.

Q1. What is the main purpose of a Message Authentication Code (MAC)?

💡 Reason: A MAC uses a secret key to generate a unique tag. This tag proves two things: 1) The message came from a trusted sender who holds the secret key (Data Origin Authentication), and 2) The message content was not tampered with during transmission (Data Integrity).

Q2. What kind of cryptographic key is used in a MAC?

💡 Reason: MAC is a symmetric key system. Both the sender (Alice) and receiver (Bob) share the exact same secret key K. Alice uses K to generate the MAC tag, and Bob uses the same K to verify it.

Q3. What happens if an attacker alters even 1 letter in a message protected by a MAC?

💡 Reason: Cryptographic MAC functions have an avalanche effect: changing even a single bit in the message payload produces a completely different MAC tag. When the receiver calculates the MAC, the mismatch immediately alerts them to the attack.

Q4. Why is a secret key needed for a MAC, instead of just using a plain hash function (like SHA-256)?

💡 Reason: Anyone can compute a plain hash H(M) because no key is required. If an attacker changes message M to M’, they could simply compute H(M’) to fool the receiver. A MAC requires the secret key K, which the attacker does not possess!

Q5. In CBC-MAC (Cipher Block Chaining MAC), how are long messages processed?

💡 Reason: CBC-MAC divides a long message into fixed 128-bit blocks. Each block is XORed with the encrypted output of the previous block before AES encryption. The final block output becomes the authentication tag, protecting all blocks together.
