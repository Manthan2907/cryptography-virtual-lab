Needham-Schroeder Symmetric Key Protocol

Estimated Time

1 hour

Learning Objective of the Experiment

To identify, trace, and analyze the steps of the Needham-Schroeder Symmetric Key Protocol (1978) for establishing a temporary shared secret key and achieving mutual authentication between two untrusted network nodes via a trusted Server (Key Distribution Center / KDC).

  • Understand the architectural role of a centralized Server (KDC) in symmetric key management.
  • Analyze how Alice's Random Challenge Number (N_A) and Bob's Random Challenge Number (N_B) prevent replay attacks.
  • Observe ticket generation and ticket forwarding mechanics.
  • Evaluate challenge-response nonce verification (N_B - 1) for mutual authentication.

Real-World Story Analogy: The Secure Bank Manager & Sealed Envelopes

Imagine Alice and Bob both have safe deposit boxes inside a high-security Bank Branch, managed by a trusted Bank Manager (Server / KDC). Alice shares a secret passcode combination with the Bank Manager (Alice's Secret Master Password), and Bob shares a different combination with the Manager (Bob's Secret Master Password). Neither Alice nor Bob knows each other's passcode.

When Alice wants to open a private line of communication with Bob, she asks the Bank Manager for a temporary one-time passcode (Temporary Shared Secret Key / Session Key). The Manager locks this temporary key inside a sealed box encrypted with Alice's passcode. Inside that same box, the Manager places a second sealed envelope (The Ticket) locked with Bob's passcode.

Alice unlocks her box, retrieves the temporary key, and hands the sealed envelope to Bob. Bob uses his secret combination to open his envelope, proving to both parties that the Bank Manager issued the temporary key!

5-Step Protocol Message Breakdown

Step 1 (A -> S): A, B, Alice Challenge Number
Step 2 (S -> A): { Alice Challenge Number, B, Temporary Session Key, { Temporary Session Key, A }BobPassword }AlicePassword
Step 3 (A -> B): { Temporary Session Key, A }BobPassword
Step 4 (B -> A): { Bob Challenge Number }SessionKey
Step 5 (A -> B): { f(Bob Challenge Number) }SessionKey where f(NB) = NB - 1

Security Analysis & The Denning-Sacco Vulnerability

In 1981, Dorothy Denning and Giovanni Sacco identified a major flaw in the original 1978 protocol: Step 3's ticket contains no timestamp or Bob-generated challenge. If a hacker steals an old temporary session key, they can replay the old ticket to Bob. Bob will unlock it with his password and accept the compromised key! Modern systems (like Kerberos) fix this by embedding encrypted timestamps inside tickets.

Simulation Instructions

Follow these instructions to configure, run, and inspect the Needham-Schroeder protocol in the interactive simulation:

Step 1: Configure Identities & Challenge Mode

On the Interactive Simulation tab, select Client A Identity (Alice), Client B Identity (Bob), and choose the Challenge Number Mode (Auto 16-bit Hex Nonces or Fixed Demo Values).

Step 2: Initialize Protocol Handshake

Click "Initialize Handshake". This generates 16-bit challenge numbers and transmits Step 1 (A -> S) requesting a temporary session key from the Server.

Step 3: Step-by-Step Execution

Click "Next Step" to step through transmissions 2 to 5. Watch the data packet traverse the topology map and monitor node status badges.

Step 4: Payload & Plain English Story Inspection

Review the Message Inspection Panel for raw wire format ciphertext, decrypted field tables, and the Plain English Story column for layman explanations.
