Access Control Fundamentals

Study and implement an access control mechanism to determine whether a subject is permitted to perform a requested operation on an object.

Aim & Objectives

Aim: Study and implement an access control mechanism to determine whether a subject is permitted to perform a requested operation on an object.

Objectives:

  • Distinguish between subjects, objects, operations, and permissions.
  • Examine Discretionary Access Control (DAC), Mandatory Access Control (MAC), and Role-Based Access Control (RBAC).
  • Simulate policy enforcement decisions and authorization checks.

Theory

Access control is a fundamental component of data security that dictates who is allowed to access and use company information and resources. Through authentication and authorization, access control policies ensure that users are who they say they are and that they have appropriate access to company data.

In computer security, access control involves three primary abstractions: Subjects, Objects, and Operations. A Subject is an active entity, such as a user, process, or device, that requests access to a resource. An Object is a passive resource, such as a file, database record, network port, or hardware device, that is being accessed. An Operation is the specific action the subject wishes to perform on the object, typically categorized as Read, Write, Execute, or Delete.

1. Discretionary Access Control (DAC)

Discretionary Access Control (DAC) is a model where the owner of an object has complete control over it. The owner can grant or deny access to other subjects at their discretion. This is typically implemented using Access Control Lists (ACLs). While flexible, DAC can be vulnerable to compromised user accounts and malicious programs like Trojan horses, because any program run by a user inherits all of that user's privileges.

2. Mandatory Access Control (MAC)

Mandatory Access Control (MAC) is a strict, centrally managed access control model often used in high-security environments like government and military. In MAC, both subjects and objects are assigned security labels or clearances (e.g., Unclassified, Confidential, Secret, Top Secret). Access decisions are strictly enforced by the operating system based on these labels, following security rules such as the Bell-LaPadula model (for confidentiality) which dictates "no read up, no write down", or the Biba model (for integrity). Users cannot override these policies.

3. Role-Based Access Control (RBAC)

Role-Based Access Control (RBAC) simplifies management by grouping permissions into roles rather than assigning them directly to individual users. Users are then assigned to one or more roles (e.g., Administrator, Faculty, Student), and they inherit the permissions associated with those roles. This model aligns closely with organizational structures and greatly reduces the administrative overhead of managing user access, especially in large organizations. It enforces the principle of least privilege by ensuring users only have the access necessary for their specific job functions.

Procedure

  1. Select the desired Access Control Model (DAC, MAC, or RBAC).
  2. Enter the requesting Subject Identity (e.g., Alice, Bob, Admin).
  3. Select the Subject Role/Clearance representing the user's privilege level.
  4. Select the target Object you wish to access.
  5. Select the requested Operation (Read, Write, Execute, Delete).
  6. Click "Evaluate Access Request" to observe the authorization decision and audit log.
