Access Control Fundamentals

Study and implement an access control mechanism to determine whether a subject is permitted to perform a requested operation on an object.

Aim & Objectives

Aim: Study and implement an access control mechanism to determine whether a subject is permitted to perform a requested operation on an object.

Objectives:

  • Distinguish between subjects, objects, operations, and permissions.
  • Examine Discretionary Access Control (DAC), Mandatory Access Control (MAC), and Role-Based Access Control (RBAC).
  • Simulate policy enforcement decisions and authorization checks.

Theory

Access control is a fundamental component of data security that dictates who is allowed to access and use company information and resources. Through authentication and authorization, access control policies ensure that users are who they say they are and that they have appropriate access to company data.

The Core Abstractions:
  • Subject: An active entity (e.g., user, process, device) that requests access to a resource.
  • Object: A passive resource (e.g., file, database record, hardware) that is being accessed.
  • Operation: The specific action (Read, Write, Execute, Delete) requested by the subject.

1. Discretionary Access Control (DAC)

A model where the owner of an object has complete control over it. The owner can grant or deny access to other subjects at their discretion using Access Control Lists (ACLs).

Vulnerability: Can be compromised by malicious programs (like Trojans) since programs inherit the user's privileges.

2. Mandatory Access Control (MAC)

A strict, centrally managed model used in high-security environments. Subjects and objects are assigned security clearances and classifications.

Rules: Enforces policies like Bell-LaPadula (confidentiality: "no read up, no write down") and Biba (integrity).

3. Role-Based Access Control (RBAC)

Simplifies management by grouping permissions into predefined roles. Users are assigned roles and inherit the associated permissions.

Advantage: Aligns with organizational structures and naturally enforces the principle of least privilege.

Procedure

  1. Select Model: Choose the desired Access Control Model (DAC, MAC, or RBAC) from the button group.
  2. Identify Subject: Enter the requesting Subject Identity (e.g., User A, Administrator).
  3. Assign Clearance/Role: Select the Subject Role representing their privilege tier.
  4. Target Object: Select the resource the subject intends to interact with.
  5. Determine Operation: Pick the action to perform (Read, Write, Execute, Delete).
  6. Evaluate & Observe: Click "Evaluate Access Request" and review the resulting authorization decision in the Audit Log.

Self-Assessment Quiz

Test your knowledge on Access Control Fundamentals. Select an answer to see instant feedback.

1. What does the "Subject" refer to in access control?

Explanation: A Subject is an active entity that initiates a request, whereas an Object is the passive resource being targeted.

2. Which access control model assigns access rights strictly based on the classification of data and the clearance of users?

Explanation: MAC enforces policies globally using data classifications (e.g., Secret) and user clearances, typical in military/government environments.

3. In Discretionary Access Control (DAC), who decides the access permissions for a resource?

Explanation: In DAC, the owner of an object has full discretion to grant or revoke access to other subjects.

4. What is a primary advantage of Role-Based Access Control (RBAC) over DAC and MAC?

Explanation: RBAC aligns directly with organizational structure, allowing permissions to be assigned to job functions (roles) rather than managing individual user accounts separately.

5. In the Bell-LaPadula MAC model, which principle prevents a user from viewing data classified at a higher security level than their clearance?

Explanation: "No Read Up" ensures confidentiality by stopping subjects from accessing information above their clearance level.

6. What is the fundamental difference between Authentication and Authorization?

Explanation: Authentication confirms identity (e.g., via password). Authorization is the access control mechanism that checks if that verified identity has permission to perform an action.

7. Why is DAC considered more vulnerable to malware like Trojan horses than MAC?

Explanation: In DAC, if an administrator accidentally runs a Trojan, the Trojan acts with the administrator's full privileges and can modify files on their behalf. MAC restricts this via global labeling.

8. Under the Biba Integrity Model (a form of MAC), what rule prevents lower-integrity data from contaminating higher-integrity data?

Explanation: The Biba model enforces "No Write Up", preventing a low-integrity subject from overwriting or corrupting high-integrity objects.

9. If a hospital restricts doctors to accessing only the records of their own current patients, this is an example of applying which core security principle?

Explanation: The "Need to Know" principle restricts access strictly to the information required to perform one's current job function.

10. In the context of access control, what is an "Operation"?

Explanation: Operations (also called Access Modes) define exactly what a subject is attempting to do to the target object.
