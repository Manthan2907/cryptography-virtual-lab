RSA as a Digital Signature

Generate an RSA digital signature for a given message and verify the signature using the corresponding public key.

Assigned Group: Arnav Potale, Joel Wilson, Omkar Patil, Rahul Senapati • Branch: group-rsa

Aim & Overview

Aim: To generate an RSA digital signature for a given message and verify the signature using the corresponding public key.

Key Learning Objectives

  • Understand how asymmetric public-key cryptography enables message authentication and integrity.
  • Learn how the RSA key pair (Public Key and Private Key) is mathematically constructed from prime numbers.
  • Observe digital signature creation using the signer's private exponent: s = m^d mod n.
  • Perform digital signature verification using the signer's public exponent: m' = s^e mod n.
  • Simulate man-in-the-middle message interception and observe how tampering invalidates the signature.

Core Theory of RSA Digital Signatures

A digital signature is a mathematical technique that binds a sender to a message, proving who sent it and that it was not modified in transit.

Concept 1

A. What is RSA?

RSA is an asymmetric (public-key) cryptographic algorithm. It uses two mathematically linked keys:

  • Public Key (e, n): Shared openly with anyone to verify signatures.
  • Private Key (d, n): Kept secret by the signer to generate signatures.

In this experiment, RSA is used to create and verify a digital signature.

Concept 2

B. How are Keys Created?

1. Choose primes: p and q
2. Calculate: n = p × q
3. Calculate: phi(n) = (p - 1)(q - 1)
4. Choose e such that: gcd(e, phi(n)) = 1
5. Calculate d: e × d ≡ 1 (mod phi(n))
Public Key: (e, n)   Private Key: (d, n)
d is the private exponent used to generate the signature. Only the signer knows d, ensuring nobody else can forge the signature.
e must have a modular inverse modulo phi(n), which is only possible when gcd(e, phi(n)) = 1.
Concept 3

C. How is the Message Signed?

The sender uses their secret private key exponent d:

s = m^d mod n

MESSAGE → Private Key (d, n) → SIGNATURE (s)

The numerical message m must satisfy 0 < m < n.

Concept 4

D. How is the Signature Verified?

The receiver uses the signer's public key exponent e:

m' = s^e mod n
If m' = m → VALID SIGNATURE
Anyone with the public key can check whether the signature matches the message without needing the secret private key.
Concept 5

E. What Does a Digital Signature Show?

1. Authentication

Confirms the message came from the entity holding private key d.

2. Message Integrity

Any change to message m causes verification to fail immediately.

3. Non-Repudiation

The signer cannot deny signing because only they possess private key d.

Important Security Note: A digital signature does NOT provide confidentiality. The message itself is transmitted in plain view alongside signature s.

STEP 4 — Calculate Private Exponent (Extended Euclidean Algorithm) Implemented by: modInverse(e, phi)
Formula: d = e⁻¹ mod phi(n) ⇔ e × d ≡ 1 (mod phi(n))
Euclidean Division Steps:
132 = 26 × 5 + 2
5 = 2 × 2 + 1
Extended Euclidean Derivation (Back-Substitution):
1 = 5 - 2 × 2
1 = 5 - 2 × (132 - 26 × 5)
1 = 53 × 5 - 2 × 132
Therefore: d = 53
Verification:
5 × 53 = 265 → 265 mod 132 = 1. Therefore d = 53 is correct.

Demonstrate what happens if an attacker intercepts the transmitted package and modifies the message before verification:

Transmitted Message: 88

⚠ Interception Mathematics: Why Verification Failed
Original Sender's Data: Message m = 88, Signature s = 11
Original Verification: s^e mod n = 11^7 mod 187 = 88 (Authentic)
Attacker Action: Alters message 88 → 89, but signature remains 11.
The attacker cannot forge a valid signature for 89 because they do not possess private key d.
Receiver's Calculation:
m' = s^e mod n = 11^7 mod 187 = 88
Received Message = 89, Recovered Message m' = 88
Comparison: 88 ≠ 89 → ✕ INVALID SIGNATURE (Tampering Detected!)
🔗 Cryptographic Hash Digest Comparison:
SHA-256(Original 88):
8b940be7fb78aaa6b6567dd7a3987996947460df1c668e698eb92ca77e425349
SHA-256(Tampered 89):
cd70bea023f752a0564abb6ed08d42c1440f2e33e29914e55e0be1595e24f45a
Digest(Original) ≠ Digest(Tampered)

This is why standardized digital-signature schemes bind the signature to a message digest rather than directly signing arbitrary-length raw message data. An attacker cannot alter even a single bit without completely altering the digest.

Conclusion

1. Verification Correctness: When the untampered signature is verified, m' = s^e mod n = 23 equals original message 23 and the calculated digest matches the signature digest representation, confirming mathematical authenticity.
2. Integrity Guarantee: When the message is altered or the hash algorithm is mismatched, the message digest changes, proving that any modification is detected immediately.
3. Unforgeability: The interceptor cannot produce a valid signature for a modified message without knowing private exponent d.
