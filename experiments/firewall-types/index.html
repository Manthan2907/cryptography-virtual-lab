Different Types of Firewalls

Compare six firewall architectures through guided traffic simulation, policy inspection and assessment.

Aim & Objectives

Aim: Analyze how different types of firewalls inspect network traffic, enforce security policies, and protect systems against unauthorized access and simulated threats.

Objectives:

  • Distinguish packet filtering, stateful inspection, circuit-level gateways, application proxies, next-generation firewalls and web application firewalls.
  • Configure traffic and firewall rules, observe packet decisions, and compare inspection capabilities.
  • Evaluate security limitations through practical scenarios and assessment questions.

Theory

A firewall applies a security policy to traffic crossing a network or application boundary. Different architectures inspect different information. An allowed connection is not proof that its content is safe; the decision depends on the configured policy and the firewall's visibility.

1. Packet Filtering

Matches network and transport header fields such as IP addresses, protocol and ports. A stateless filter evaluates each packet independently.

Fast and simple for basic network boundaries. It cannot infer whether an allowed web request carries an attack.

In this experiment: In this lab, ordered header rules apply and unmatched traffic is denied.

2. Stateful Inspection

Tracks flows and uses their connection state when deciding whether traffic belongs to an accepted exchange. State is maintained by the device, not a flag a sender may freely assert.

Useful for return traffic and blocking invalid flows. Connection tracking does not inherently inspect application payloads.

In this experiment: The lab accepts established traffic before new-flow rules and rejects invalid state.

3. Circuit-Level Gateway

A circuit gateway controls transport sessions, commonly using a SOCKS-style relay. It can validate session negotiation without understanding each application payload.

Useful for controlled session relay. It does not inherently identify SQL injection or malware in permitted content.

In this experiment: This simplified gateway requires valid TCP negotiation after header approval; UDP relay is not modeled.

4. Application-Level Gateway / Proxy

An application gateway terminates a connection and creates another on behalf of the client. It can enforce protocol-specific commands, destinations or content rules.

Fine-grained application control, with additional processing and configuration. Support depends on the proxy protocol.

In this experiment: This HTTP(S) proxy denies /admin paths. It is not a universal attack detector; HTTPS is assumed decrypted.

5. Next-Generation Firewall

NGFW products commonly combine stateful filtering with application identification and intrusion prevention. Features and policies vary by implementation.

Can identify disallowed applications and known attack signatures. Visibility into encrypted payloads requires appropriate inspection.

In this experiment: This lab combines connection state, a declared application allowlist and explicit simulated threat indicators.

6. Web Application Firewall

A WAF applies application-layer rules to HTTP requests and responses to help protect web services, including checks for common injection patterns.

Complements network firewalls. It cannot replace network controls for arbitrary SSH, DNS or other non-HTTP traffic.

In this experiment: This WAF inspects HTTP(S) path patterns and SQL injection / XSS flags. Other traffic passes through outside its scope.

Procedure

  1. Read the theory and identify what each firewall architecture can inspect.
  2. Open Simulation and select a firewall architecture.
  3. Choose Normal browsing to automatically run a baseline packet. Observe the sending, inspection and outcome stages.
  4. Choose Blocked SSH, DNS query, Suspicious payload, Malicious HTTP request or Established connection. Predict the outcome and inspect the explanation.
  5. Select Compare firewalls to evaluate the same traffic against different architectures.
  6. Open Advanced settings to change packet fields or ordered allow/deny rules. Select Apply & run and inspect the traffic log.
  7. Complete the practical assessment and ten-question quiz. Review missed topics and print the completion report if needed.
