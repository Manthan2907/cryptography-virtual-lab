HMAC Authentication and Verification

Generate, verify, and analyze HMAC values using a secret key.

Theory

1. What is HMAC?

HMAC (Hash-based Message Authentication Code) is a specific type of message authentication code (MAC) involving a cryptographic hash function and a shared secret cryptographic key. It is formally specified in RFC 2104 and standardized by NIST in FIPS PUB 198-1.

HMAC provides two fundamental security guarantees:

  • Message Authentication (Authenticity): Proves that the message was created by a party possessing the shared secret key.
  • Data Integrity: Ensures that the message has not been altered, modified, or corrupted during transit or storage.
HMAC(K, m) = H((K' ⊕ opad) ∥ H((K' ⊕ ipad) ∥ m))

K' (Derived Key)

If key K is longer than hash block size B (64 bytes for SHA-256), it is pre-hashed H(K). If shorter, it is right-padded with zeroes to block size B.

ipad (Inner Pad)

A byte 0x36 repeated B times (e.g. 64 times for SHA-256). XORed with the key before the inner hashing pass.

opad (Outer Pad)

A byte 0x5C repeated B times. XORed with the key before the outer hashing pass.

2. Why is a Secret Key Required?

A standard unkeyed hash function (like SHA-256 alone) generates a deterministic checksum. Anyone can compute a hash. If an active attacker (Man-in-the-Middle) modifies a message in transit, they could simply recalculate a new standard SHA-256 hash and replace both.

By incorporating a shared secret key known only to the sender and recipient, an attacker cannot forge a valid HMAC after modifying the message without knowledge of the secret key.

3. Why Not Just Hash H(Key ∥ Message)?

Naively concatenating Hash(Key ∥ Message) is vulnerable to Length Extension Attacks when using Merkle-Damgård hash functions (such as MD5, SHA-1, SHA-256, and SHA-512). An attacker can append arbitrary data to the end of the message and predict the new hash without ever knowing the key.

The nested two-pass construction of HMAC: H(Key_outer ∥ H(Key_inner ∥ Message)) completely neutralizes length extension attacks because the inner hash state is wrapped and hashed again with the outer key.

4. The Avalanche Effect

Due to the properties of the underlying cryptographic hash function, HMAC exhibits a strong Avalanche Effect: changing even a single bit or single character in either the message or the secret key causes approximately 50% of the output bits to flip pseudorandomly.

5. Learning Outcomes

  • Understand the operational mechanism of Keyed-Hash Message Authentication Codes.
  • Differentiate between confidentiality (encryption) and integrity/authenticity (HMAC).
  • Demonstrate how modifying a single character in the message breaks HMAC verification.
  • Demonstrate how using an incorrect or altered secret key causes verification failure.
  • Implement and evaluate HMAC generation and verification using the modern W3C Web Crypto API.

Laboratory Procedure

Follow these step-by-step instructions to perform the experiments.

Standard Experiment Workflow

  1. Navigate to the Simulation tab.
  2. Review the Simulation Controls card containing the HMAC Generator and Verifier.
  3. In the HMAC Generator section:
    • Input your message text (e.g. Hello World).
    • Enter your secret key (e.g. mysecretkey).
    • Ensure the algorithm is set to HMAC-SHA-256.
    • Click Generate HMAC.
  4. Observe the 64-character hexadecimal HMAC string rendered in the Simulation Output card.
  5. In the HMAC Verification section:
    • Click "Fill from Generator" or manually enter the message, secret key, and generated HMAC.
    • Click Verify HMAC to perform real-time verification using the Web Crypto API.
    • Confirm that the green "✓ HMAC Verified" banner is displayed.
  6. Proceed to the Modification Analysis section to explore message tampering and secret key variations:
    • Select A. Modify Message: Alter a single character (e.g. Hello World → Hello world).
    • Select B. Modify Secret Key: Alter the key casing (e.g. mysecretkey → mysecretKey).
    • Observe the resulting avalanche effect, the character diff highlighting, and the verification failure notice.
  7. Once completed, proceed to the Quiz tab to test your comprehension.
