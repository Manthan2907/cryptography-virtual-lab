Password Hashing Comparison

Explore and compare six hashing algorithms and understand how modern password hashing protects stored passwords.

Aim

To study and compare MD5, SHA-1, SHA-256, bcrypt, scrypt, and Argon2id based on their working, execution time, security, and suitability for password storage.

Objectives

  • Understand the concept of cryptographic hashing and password storage.
  • Differentiate between general-purpose hash functions and password hashing algorithms.
  • Understand the importance of random salts.
  • Compare the speed and security characteristics of six algorithms.
  • Understand computational cost and memory-hardness.
  • Identify suitable algorithms for secure password storage.

Expected Learning Outcome

After completing this experiment, students will be able to explain why modern password storage uses slow, adaptive algorithms instead of ordinary fast hash functions.

1. What is Password Hashing?

Password hashing converts a password into a fixed-length output called a hash. A hash function is designed to be one-way, meaning the original password should not be practically recoverable from the hash.

Websites should store password hashes rather than plain-text passwords. During login, the entered password is processed again and checked against the stored password hash.

2. Hashing vs Encryption

HashingEncryption
One-way process Reversible using a key
No decryption key Requires an encryption key
Used for password verification Used to protect data that must be recovered

3. What is a Salt?

A salt is a unique, randomly generated value added to a password before hashing. It ensures that identical passwords produce different stored hashes.

Example:

Password: hello123

Password + Salt A → Hash A

Password + Salt B → Hash B

Even though the password is identical, the hashes differ.

4. Types of Hashing Algorithms

MD5 (Message Digest 5)

MD5 produces a 128-bit (32 hexadecimal character) digest. It is extremely fast and has serious collision weaknesses. It should not be used for password storage.

SHA-1 (Secure Hash Algorithm 1)

SHA-1 produces a 160-bit (40 hexadecimal character) digest. It has known collision attacks and is unsuitable for password storage.

SHA-256

SHA-256 belongs to the SHA-2 family and produces a 256-bit (64 hexadecimal character) digest. It remains useful for many cryptographic applications, but is too fast to be used alone for password storage.

bcrypt

bcrypt is an adaptive password hashing algorithm based on the Blowfish cipher. Its configurable cost factor controls how much computation is required. A higher cost makes password guessing slower.

scrypt

scrypt is a memory-hard password-based key derivation function. It requires both computation and significant memory, making large-scale parallel password guessing more expensive.

Argon2id

Argon2id is a modern password hashing algorithm and a winner of the Password Hashing Competition. It combines properties of Argon2i and Argon2d and is designed to provide resistance against several types of attacks.

5. Important Security Concepts

  • Brute-force attack: An attacker tries many possible passwords until one matches.
  • Dictionary attack: An attacker tries passwords from a prepared list of common passwords.
  • Rainbow table: A precomputed collection of password hashes used to speed up hash lookup attacks.
  • Computational cost: The amount of processing required to calculate a hash.
  • Memory-hardness: The requirement for substantial memory during password hashing.

Experimental Procedure

  1. Open the Simulation section of the experiment.
  2. Enter a sample password in the password input field.

  4. Click the Run Benchmark Comparison button.

  6. Compare the output lengths and security characteristics.
  7. Use the salt demonstration to generate hashes with different random salts.
  8. Observe how the same password produces different hashes when different salts are used.
  9. Complete the assessment quiz to test your understanding.

Precautions

  • Use a sample password, not your actual account password.
  • Do not share generated passwords or hashes publicly.
  • Benchmark results depend on the device and browser.
  • Do not use MD5, SHA-1 or plain SHA-256 for real password storage.

What should you observe?

  • MD5, SHA-1 and SHA-256 generally calculate very quickly.
  • bcrypt takes more computation as its cost increases.
  • scrypt and Argon2id also use memory as part of their design.
  • Random salts make hashes different even for identical passwords.
