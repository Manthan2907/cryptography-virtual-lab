Kerberos Authentication Protocol

Interactive step-by-step visualization of ticket-based authentication across Client Alice, Authentication Server (AS), Ticket Granting Server (TGS), and Server Identity Bob.

Aim & Objectives

The objective of this experiment is to understand how the Kerberos authentication protocol securely authenticates a user and allows the user to access network services without sending the password over the network.

Understand Ticket-Based Authentication

Learn how Kerberos uses tickets instead of repeatedly sending a user's password to network servers.

Understand the Role of the KDC

Understand how the Key Distribution Center (KDC) acts as a trusted authority that helps authenticate users and provide secure tickets.

Understand Secure Service Access

Observe how a user obtains a Ticket Granting Ticket (TGT) and then uses it to obtain a Service Ticket for accessing a particular server.

What is Kerberos?

Kerberos is a network authentication protocol used to securely verify the identity of users and services over an untrusted network.

Instead of sending a password every time a user wants to access a service, Kerberos uses encrypted tickets and temporary session keys.

Kerberos works with the help of a trusted third party called the Key Distribution Center (KDC).

Why is Kerberos Used?

Sending passwords repeatedly over a network can expose them to attackers. Kerberos avoids this by using tickets.

No Password Transmission

The user's password is not sent to the network server when requesting a service.

Single Sign-On

The user authenticates once and can then access multiple authorized services without entering the password again.

Replay Protection

Kerberos uses timestamps and authenticators to help prevent old authentication messages from being reused by an attacker.

Main Components of Kerberos

Kerberos mainly involves four participants:

1. Client (Alice)

The user requesting access to a network service.

2. Authentication Server (AS)

Performs the initial authentication and provides a Ticket Granting Ticket (TGT).

3. Ticket Granting Server (TGS)

Provides a Service Ticket for the requested server.

4. Server (Bob)

The service or resource that Alice wants to access.

Note: The Authentication Server (AS) and Ticket Granting Server (TGS) together form the Key Distribution Center (KDC).

How Kerberos Authentication Works

Kerberos authentication can be understood in three simple stages:

1

Get a TGT

Alice first contacts the Authentication Server and authenticates herself. The AS provides Alice with a TGT and a temporary session key.

↓
2

Get a Service Ticket

Alice sends her TGT to the Ticket Granting Server and requests access to Bob's service. The TGS verifies the request and provides a Service Ticket.

↓
3

Access the Server

Alice sends the Service Ticket and an Authenticator to Bob. Bob verifies them and, if everything is valid, grants Alice access.

Security Features of Kerberos

Feature How Kerberos Provides It
Authentication Verifies the identity of users and services.
Single Sign-On User authenticates once and reuses tickets.
Password Protection Password is not repeatedly transmitted over the network.
Mutual Authentication Client and server can verify each other's identity.
Replay Protection Timestamps and authenticators help prevent replay attacks.
Secure Communication Temporary session keys are used for communication.

Initialize the Simulation

Click Initialize Simulation to create the initial parameters for the authentication exchange.

2

Send AS-REQ

Click Send AS-REQ to send Alice's authentication request to the Authentication Server (AS).

Observe the request moving from Alice to the AS and note the timestamp generated for the request.

3

Receive the TGT — AS-REP

Click Generate TGT to simulate the response from the Authentication Server.

Observe the generated Ticket Granting Ticket (TGT) and the client-TGS session key Kc,tgs.

4

Request a Service Ticket — TGS-REQ

Click Send TGS-REQ to send Alice's TGT to the Ticket Granting Server (TGS).

The request also contains an Authenticator and identifies Bob as the server Alice wants to access.

5

Receive the Service Ticket — TGS-REP

Click Generate Service Ticket to simulate the TGS response.

Observe the generated Service Ticket (ST) and the client-server session key Kc,v.

6

Send the Service Request — AP-REQ

Click Send Service Request to send the Service Ticket and Authenticator to Bob.

Observe Bob checking the Service Ticket, Authenticator, and request freshness before accepting the authentication request.

7

Verify the Authentication Result

After Bob successfully verifies the request, observe the Authentication Successful message and the completed protocol checklist.

Click Reset Simulation if you want to perform the authentication process again with new generated values.
