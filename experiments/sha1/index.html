SHA-1 Secure Hash Algorithm

Experiment Aim

To implement, trace, and evaluate the SHA-1 (Secure Hash Algorithm 1) cryptographic hashing algorithm; to examine its message preprocessing, 512-bit block parsing, 80-word message schedule expansion ($W_0 \dots W_{79}$), and 80-step four-stage non-linear compression rounds; and to quantitatively demonstrate the Avalanche Effect and cryptanalytic security boundaries through interactive simulation.

1. Introduction to the SHA-1 Algorithm

The Secure Hash Algorithm 1 (SHA-1) is an iterated cryptographic hash function designed by the United States National Security Agency (NSA) and published as a U.S. Federal Information Processing Standard (FIPS PUB 180-1) by NIST in 1995. It was developed to succeed SHA-0 by introducing a 1-bit circular left shift in the message expansion schedule to prevent differential cryptanalytic attacks.

SHA-1 maps an arbitrary-length message (up to $2^{64}-1$ bits) into a fixed-size 160-bit (20-byte) message digest, rendered as a 40-character hexadecimal string. Like MD5, SHA-1 is based on the Merkle–Damgård construction, but operates with five 32-bit registers across 80 compression rounds.

2. Fundamental Cryptographic Properties

A secure cryptographic hash function $H$ must fulfill three primary security properties:

  • Pre-image Resistance (One-Way): Given any hash output $h$, it is computationally infeasible to find an input message $M$ such that $H(M) = h$.
  • Second Pre-image Resistance (Weak Collision Resistance): Given an input message $M_1$, it is computationally infeasible to find another distinct message $M_2 \neq M_1$ such that $H(M_1) = H(M_2)$.
  • Collision Resistance (Strong Collision Resistance): It is computationally infeasible to find any two distinct messages $M_1 \neq M_2$ such that $H(M_1) = H(M_2)$.

4. Mathematical Architecture & Execution Pipeline

Processing an input message through SHA-1 involves five mathematical phases:

Phase 1: Message Padding (RFC 3174 §4)

The message of bit-length $L$ is padded so that its bit length is congruent to 448 modulo 512 (equivalent to 56 bytes modulo 64). Padding is always performed, even if the message already has the desired length.

Padding Structure: [Original Message (L bits)] + [1 bit '1' (byte 0x80)] + [k zero bits '0' (0x00 bytes)] where (L + 1 + k) mod 512 ≡ 448 (with 0 ≤ k ≤ 511 bits)

Phase 2: Appending 64-bit Length Value

A 64-bit unsigned representation of the original message bit-length $L$ is appended to the message. In SHA-1, this length is encoded in Big-Endian format (most significant byte first). The padded message now has an exact multiple of 512 bits:

Total Padded Length: N × 512 bits = N × 64 bytes = N × 16 (32-bit words)

Phase 3: Initializing 160-bit Chaining Variables

A five-word (160-bit) buffer of chaining registers ($H_0, H_1, H_2, H_3, H_4$) is initialized with standard hexadecimal constants:

Initial Register Constants (IV): H0 = 0x67452301 H1 = 0xEFCDAB89 H2 = 0x98BADCFE H3 = 0x10325476 H4 = 0xC3D2E1F0

Phase 4: Message Schedule Expansion ($W_0 \dots W_{79}$)

Each 512-bit block is parsed into sixteen 32-bit big-endian words $W_0 \dots W_{15}$. These are expanded into 80 words $W_0 \dots W_{79}$ using the recurrence formula:

Schedule Expansion (for t = 16 to 79): W[t] = ROTL1( W[t-3] ⊕ W[t-8] ⊕ W[t-14] ⊕ W[t-16] ) where ROTLn(X) = (X « n) | (X » (32 - n))
Architectural Note: The 1-bit left circular rotation ($\text{ROTL}^1$) was the sole modification introduced in SHA-1 compared to the original SHA-0. This critical shift introduced early diffusion and disrupted linear cryptanalytic equations.

Phase 5: 80 Rounds of Compression (4 Stages × 20 Steps)

The 80 steps are grouped into 4 distinct functional stages of 20 steps each:

Stage Steps ($t$) Non-linear Function $f_t(B, C, D)$ Function Name Additive Constant $K_t$ Mathematical Derivation
Stage 1 0 – 19 (B & C) | (~B & D) Ch (Conditional / Choose) 0x5A827999 $\lfloor 2^{30} \times \sqrt{2} \rfloor$
Stage 2 20 – 39 B ^ C ^ D Parity (Bitwise XOR) 0x6ED9EBA1 $\lfloor 2^{30} \times \sqrt{3} \rfloor$
Stage 3 40 – 59 (B & C) | (B & D) | (C & D) Maj (Majority) 0x8F1BBCDC $\lfloor 2^{30} \times \sqrt{5} \rfloor$
Stage 4 60 – 79 B ^ C ^ D Parity (Bitwise XOR) 0xCA62C1D6 $\lfloor 2^{30} \times \sqrt{10} \rfloor$

At each step $t$ ($0 \le t \le 79$), the working registers update according to:

Per-Step Transformation: TEMP = (ROTL5(A) + ft(B, C, D) + E + W[t] + Kt) mod 232 E = D D = C C = ROTL30(B) B = A A = TEMP

Phase 6: Merkle–Damgård Accumulation & Big-Endian Digest Assembly

After completing 80 steps for a block, the working registers are accumulated into the chaining variables:

Chaining Variable Update: H0 = (H0 + A) mod 232 H1 = (H1 + B) mod 232 H2 = (H2 + C) mod 232 H3 = (H3 + D) mod 232 H4 = (H4 + E) mod 232

The final 160-bit digest is the big-endian concatenation of $H_0, H_1, H_2, H_3, H_4$, yielding a 40-character lowercase hexadecimal string.

5. Avalanche Effect & Strict Avalanche Criterion (SAC)

The Avalanche Effect is a vital cryptographic metric. A function satisfies the Strict Avalanche Criterion (SAC) if flipping any single bit in the input causes each output bit to flip with a probability of 50%. For SHA-1, flipping one bit or character in the input should invert approximately 80 ± 8 bits out of the 160 output bits.

6. Security Status & Modern Cryptanalysis

In 2005, cryptanalysts Xiaoyun Wang, Yiqun Lisa Yin, and Hongbo Yu presented theoretical collision attacks against full SHA-1 requiring $2^{69}$ operations (substantially less than the $2^{80}$ birthday bound). In 2017, researchers from CWI Amsterdam and Google achieved the landmark SHAttered attack, constructing the first real-world collision: two distinct PDF documents with identical SHA-1 hashes.

Deprecation Notice: SHA-1 is cryptographically broken for collision resistance and must never be used in digital signatures, TLS certificates, or authentication mechanisms. Industry standards require transitioning to SHA-256 / SHA-512 (SHA-2) or SHA-3 (Keccak).

Knowledge Check & Assessment Quiz

Answer all 10 questions below to evaluate your theoretical and algorithmic mastery of the SHA-1 algorithm, RFC 3174 padding, compression stages, and security cryptanalysis.

1. What is the fixed output digest size produced by the SHA-1 hashing algorithm?
Explanation: SHA-1 maintains five 32-bit registers ($A, B, C, D, E$), producing an exact 160-bit digest represented by 40 hexadecimal characters. In contrast, MD5 is 128 bits and SHA-256 is 256 bits.
2. What block size does SHA-1 process at each Merkle–Damgård compression iteration?
Explanation: The SHA-1 compression function operates on 512-bit (64-byte) blocks partitioned into sixteen 32-bit words ($W_0 \dots W_{15}$).
3. How many total compression steps (operations) does SHA-1 execute for each 512-bit block?
Explanation: SHA-1 executes 80 compression steps, structured as 4 stages of 20 steps each ($t = 0 \dots 79$). MD5 uses 64 steps (4 × 16).
4. Which sequence correctly lists the non-linear auxiliary functions used across the 4 stages of SHA-1?
Explanation: Steps 0–19 use Ch ($f(b,c,d) = (b \land c) \lor (\neg b \land d)$), steps 20–39 use Parity ($b \oplus c \oplus d$), steps 40–59 use Maj ($ (b \land c) \lor (b \land d) \lor (c \land d) $), and steps 60–79 use Parity again.
5. How does SHA-1 expand the 16 original block words ($W_0 \dots W_{15}$) into 80 words ($W_{16} \dots W_{79}$)?
Explanation: FIPS PUB 180-1 defines $W_t = \text{ROTL}^1(W_{t-3} \oplus W_{t-8} \oplus W_{t-14} \oplus W_{t-16})$. The 1-bit circular left shift was the critical modification distinguishing SHA-1 from SHA-0.
6. For a 3-character message ("abc" = 24 bits), how many zero bytes are added after the 0x80 byte during padding?
Explanation: The message before the 8-byte length field must equal 56 bytes (448 mod 512). The 3 message bytes + 1 byte (0x80) = 4 bytes. Thus, 56 - 4 = 52 zero bytes (416 zero bits) are appended.
7. How is the original message bit-length encoded and appended during SHA-1 preprocessing?
Explanation: SHA-1 appends the original message bit-length as a 64-bit unsigned Big-Endian integer (most significant byte first). Note that MD5 uses little-endian.
8. What does the Strict Avalanche Criterion (SAC) predict when a single input bit is flipped in SHA-1?
Explanation: SAC requires that each output bit flips with a probability of 0.5 when an input bit changes, producing roughly 80 changed bits across the 160-bit SHA-1 digest.
9. What was achieved by the landmark "SHAttered" attack in 2017 (CWI Amsterdam & Google)?
Explanation: Stevens et al. created two different PDF files with identical SHA-1 hashes (approx. 9 quintillion SHA-1 computations), providing undeniable proof that SHA-1's collision resistance is broken.
10. What hash algorithm family is universally recommended by NIST to replace SHA-1 for digital signatures?
Explanation: NIST SP 800-131A mandated transitioning from SHA-1 to SHA-2 (specifically SHA-256, SHA-384, SHA-512) or SHA-3 for digital certificates, signatures, and cryptographic authentication.
