Message Authentication Code (MAC)

Generate and verify a Message Authentication Code (MAC) for a given message using a shared secret key.

Aim & Objectives

The primary objective of this experiment is to implement, analyze, and verify a Message Authentication Code (MAC) for arbitrary messages using a shared secret key K. Students will explore how MAC provides data integrity and data origin authentication, and observe how an attacker who modifies the message but cannot forge a valid MAC is detected by the receiver.

Data Origin Authentication

Proving that the transmitted payload M was generated by a legitimate sender who holds the shared secret key K.

Data Integrity Verification

Detecting any unauthorized modifications, insertions, or payload alterations introduced by an attacker in transit.

Tamper Detection

Demonstrating that an attacker who modifies the message but must use a random key to forge a MAC tag will always be detected by the receiver.

What is a Message Authentication Code (MAC)?

A Message Authentication Code (MAC) is a symmetric key cryptographic algorithm that takes an arbitrary-length message payload M and a shared secret key K, and produces a fixed-size authentication tag T:

Tag T = MAC(K, M)

Only parties who possess the secret key K can compute or verify the tag T. If an adversary modifies even 1 bit of M but cannot recompute the MAC (because they don’t have K), the receiver’s verification algorithm detects the tampering.

How MAC Works: Sender → Attacker → Receiver Flow

1. Sender Side

The sender enters a message M and a secret key K (mutually agreed with the receiver). The MAC algorithm processes both to generate a tag T = MAC(K, M). The sender then transmits M || T (message appended with MAC).

2. Attacker (Man-in-the-Middle)

An attacker (if enabled) intercepts the transmission. They modify the message M to M', but since they don’t know the secret key K, they generate a forged MAC T' using a random key. They forward M' || T' to the receiver.

3. Receiver Side

The receiver has the same shared key K. They compute T' = MAC(K, M') on the received message and compare it with the received tag T. Since M' ≠ M, the computed T' ≠ T, and tampering is detected.

Security Properties: MAC vs. Hash vs. Digital Signature

Security Mechanism Key Used Data Integrity Authentication Non-Repudiation
Cryptographic Hash (SHA-256) None Yes (accidental noise) No No
MAC (Keyed-MAC) Shared Secret K Yes (active tampering) Yes (key holder) No (both hold K)
Digital Signature (RSA / ECDSA) Asymmetric (Private/Public) Yes Yes Yes (only sender holds Private Key)

MAC Process Flow Diagram

The diagram below illustrates the end-to-end flow of Message Authentication Code (MAC) generation at the sender, transmission across an untrusted channel, and verification at the receiver.

Step 1

Sender Enters Message & Key

The sender enters a plaintext message and a secret key value (mutually agreed with the receiver). The MAC algorithm (HMAC-SHA256) processes both to generate a MAC tag.

Step 2

MAC Appended & Transmitted

The generated MAC tag is appended to the original message. This combined payload M || MAC is transmitted over the channel toward the receiver.

Step 3

Attacker Intercepts & Modifies

An attacker (if enabled) intercepts the transmission. The attacker modifies the message content but does not know the secret key, so they generate a forged MAC using a random key and forward it with the modified message.

Step 4

Receiver Verifies MAC

The receiver uses the same secret key to compute the MAC on the received message. If the computed MAC matches the received MAC, the message is authentic. If it doesn’t match, tampering is detected.

Expected Observations

  • The same key + message always produces the same MAC tag (deterministic).
  • Even a single character change in the message produces a completely different tag (avalanche effect).
  • When no attacker modifies the message, receiver verification succeeds.
  • When the attacker modifies the message but uses the sender’s original MAC, receiver verification fails - tampering detected.
  • The attacker cannot forge a valid MAC because they don’t possess the secret key.

Self-Assessment Quiz

Test your understanding of Message Authentication Codes (MAC). Select an answer for each question and click Submit for instant explanations.

Q1. What is the main purpose of a Message Authentication Code (MAC)?

Reason: A MAC uses a secret key to generate a unique tag. This tag proves two things: 1) The message came from a trusted sender who holds the secret key (Data Origin Authentication), and 2) The message content was not tampered with during transmission (Data Integrity).

Q2. What kind of cryptographic key is used in a MAC?

Reason: MAC is a symmetric key system. Both the sender (Alice) and receiver (Bob) share the exact same secret key K. Alice uses K to generate the MAC tag, and Bob uses the same K to verify it.

Q3. What happens if an attacker modifies the message but uses a random key to forge a MAC tag?

Reason: When the receiver computes MAC(K, M') using the actual secret key K, the result will be completely different from the attacker's forged MAC(random_key, M'). The mismatch immediately reveals the attack.

Q4. Why is a secret key needed for a MAC, instead of just using a plain hash function (like SHA-256)?

Reason: Anyone can compute a plain hash H(M) because no key is required. If an attacker changes message M to M’, they could simply compute H(M’) to fool the receiver. A MAC requires the secret key K, which the attacker does not possess!

Q5. In the simulation, why does the attacker use a random key to generate a forged MAC for the modified message?

Reason: The MAC algorithm requires a secret key as input. Without the actual shared key K, the attacker's only option to create a new MAC for their modified message is to guess a key (generate a random one). Since it won't match K, the receiver will catch them.
