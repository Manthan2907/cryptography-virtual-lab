Needham-Schroeder Symmetric Key Protocol

Estimated Time

1 hour

Learning Objective of the Experiment

To identify, trace, and analyze the steps of the Needham-Schroeder Symmetric Key Protocol for establishing a shared secret key ($K_{AB}$) and achieving mutual authentication between two untrusted network nodes via a trusted Key Distribution Center (KDC).

  • Understand the role of a centralized Key Distribution Center (KDC) in symmetric cryptography.
  • Analyze the usage of nonces ($N_A, N_B$) to guarantee payload freshness and prevent replay attacks.
  • Observe ticket generation $\{K_{AB}, A\}_{K_B}$ and ticket forwarding mechanics.
  • Evaluate challenge-response nonce verification ($N_B - 1$) for mutual authentication.

🔍 Overview of Symmetric Key Establishment

In symmetric cryptography, two communicating parties (Alice and Bob) must share a secret key $K_{AB}$ to secure their messages. However, pre-sharing individual symmetric keys between every pair of users in a network of $N$ users requires $O(N^2)$ secret keys. A Key Distribution Center (KDC) solves this scalability problem by requiring each user to share only one master key with the KDC ($K_A$ for Alice, $K_B$ for Bob).

📌 Protocol Message Breakdown

The Needham-Schroeder symmetric protocol consists of 5 distinct message transmissions:

Step 1 (A → S): A, B, N_A
Step 2 (S → A): { N_A, B, K_AB, { K_AB, A }_{K_B} }_{K_A}
Step 3 (A → B): { K_AB, A }_{K_B}
Step 4 (B → A): { N_B }_{K_AB}
Step 5 (A → B): { f(N_B) }_{K_AB}  (where f(N_B) = N_B - 1)

⚠️ Cryptographic Properties & Vulnerabilities

Freshness Guarantee: Alice verifies that Step 2 contains her original nonce $N_A$. Because $N_A$ is encrypted under $K_A$, only KDC could have generated this response.

The Denning-Sacco Vulnerability (1981): Step 3's ticket $\{K_{AB}, A\}_{K_B}$ does not contain a timestamp or Bob-generated nonce. If an adversary compromises an old session key $K_{AB,old}$, she can replay $\{K_{AB,old}, A\}_{K_B}$ to Bob, who cannot verify its freshness. Modern implementations (such as Kerberos) solve this by embedding encrypted timestamps into tickets.

📝 Simulation Instructions

Follow these steps to configure, run, and inspect the Needham-Schroeder Symmetric Key Protocol in the interactive workspace:

Step 1: Configure Identities & Nonce Mode

Select the Client A identity (Alice), Client B identity (Bob), and choose the Nonce Generation Mode: Auto 16-bit Hex (randomized nonces) or Fixed Demo Values.

Step 2: Initialize Protocol Handshake

Click "Initialize Handshake". This triggers Step 1 ($A \to S$), transmitting Alice's request payload containing her ID, Bob's ID, and fresh nonce $N_A$.

Step 3: Step-by-Step Execution

Click "Next Step" to advance through Steps 2 to 5. Observe the animated envelope traversing between nodes and real-time state badge updates (*Encrypting*, *Decrypting*, *Authenticated*).

Step 4: Inspect Message Payloads

Review the Message Inspector Panel at the bottom of the simulation tab to analyze raw ciphertext, mathematical formulas, decrypted field tables, and cryptographic explanations.
