# Experiment API Specifications

These are browser-side contracts for the experiment modules. Every group must expose a clear user action and render readable output in its simulation section. Use a maintained client-side library where implementing a modern primitive from scratch would be unsafe or misleading.

## Hash Functions

Experiments: MD5, SHA-1.

- Input: UTF-8 text from a user-controlled text field
- Output: lowercase hexadecimal digest
- Library: `crypto-js` or the Web Crypto API where supported
- Example: input `abc`; MD5 output `900150983cd24fb0d6963f7d28e17f72`; SHA-1 output `a9993e364706816aba3e25717850c26c9cd0d89d`

## RSA

- Input: small demonstration message and key parameters generated by the experiment
- Output: public key, private key, ciphertext, and recovered plaintext or signature verification result
- Library: `jsbn`, `node-forge`, or Web Crypto API; label small-number demonstrations as educational only
- Example: encrypt `HELLO`, decrypt it, and show whether the recovered message matches

## MAC and HMAC

- Input: message and secret key
- Output: authentication tag and verification result for original and modified messages
- Library: `crypto-js` for HMAC or Web Crypto API
- Example: changing one character must make verification fail

## Kerberos and Needham-Schroeder

- Input: client identity, service identity, nonce, and shared/session-key placeholders
- Output: ordered protocol messages, generated session value, and replay or freshness explanation
- Library: none required; these are protocol visualizations, not production authentication
- Example: show an authentication request, ticket exchange, and validation of the nonce

## Password Hashing

Experiments: bcrypt, Argon2, Argon2id.

- Input: password and cost/work-factor settings
- Output: encoded password hash, elapsed-time estimate, and verification result
- Library: `bcryptjs` and a browser-compatible Argon2 implementation
- Example: hash `correct horse battery staple`, verify the correct password, and reject a changed password

## Classical Encryption

- Input: plaintext, key, and selected cipher such as Caesar or Vigenere
- Output: ciphertext and decrypted plaintext
- Library: none required for the educational algorithms
- Example: encrypt `ATTACKATDAWN`, decrypt it, and compare with the original

## Extended Euclidean Algorithm

- Input: integers `a` and `b`
- Output: gcd and coefficients `x`, `y` satisfying `ax + by = gcd(a,b)`; modular inverse when it exists
- Library: none
- Example: for `a=17`, `m=3120`, show inverse `2753`

## Brute Force and Dictionary Attack

- Input: short demonstration secret and a bounded candidate set supplied by the experiment
- Output: attempts, match status, and elapsed time
- Library: none
- Safety: use toy secrets and never transmit or target real credentials
- Example: recover a four-character demo secret from a local candidate space

## Frequency Analysis

- Input: ciphertext and language/frequency profile
- Output: character frequency table and a candidate plaintext or substitution mapping
- Library: none
- Example: display the most common ciphertext letters and compare them to English frequencies

## SSL/TLS

- Input: simulated client/server parameters and certificate metadata
- Output: ordered handshake stages, negotiated algorithm labels, and connection status
- Library: none required for the visualization
- Example: show ClientHello, ServerHello, certificate, key exchange, and Finished messages
